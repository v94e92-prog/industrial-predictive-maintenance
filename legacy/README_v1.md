# Предиктивная аналитика: прогнозирование отказов оборудования
Учебный прототип предиктивного обслуживания (Predictive Maintenance) промышленного оборудования на **синтетических данных**. Проект демонстрирует полный цикл работы с данными датчиков: генерация временных рядов, инженерия признаков (Feature Engineering), обучение модели машинного обучения, оценка качества и анализ важности признаков.

## Что реализовано
- **Генерация данных.** Циклические временные ряды работы оборудования: 1000 часовых шагов, 5 циклов износа. Вибрация и температура растут к концу цикла, давление шумит около нормы. Состояние «отказ» размечено правилом: вибрация выше порога или температура выше порога.
- **Инженерия признаков.** Скользящие средние (`rolling mean`, окно 5 часов) для сглаживания и приращения (`diff`) для скорости изменения параметров.
- **Хронологическое разделение.** Выборка делится 80/20 без перемешивания: обучение на первых 800 часах, тест на последних 200. Это защищает от утечки данных из будущего.
- **Обучение с учётом весов классов.** Random Forest Classifier с `class_weight='balanced'` для несбалансированных классов.
- **Оценка качества.** Precision, Recall, F1-score, матрица ошибок, график важности признаков.

## Результаты
На отложенной хронологической выборке (200 точек: 160 штатной работы, 40 «отказ»):

| Метрика | Значение |
|---|---|
| Accuracy | 98% |
| Recall (класс «отказ») | 100% |
| Precision (класс «отказ») | 93% |

**Как читать эти цифры.** Метка «отказ» задана пороговым правилом по тем же показаниям (вибрация, температура), которые подаются в модель. Поэтому высокие метрики показывают, что пайплайн работает и модель воспроизводит заданное правило. Они не говорят о способности предсказывать реальные отказы.

## Ограничения
- Данные синтетические, реального оборудования и телеметрии в проекте нет.
- Все циклы устроены одинаково, тестовая часть по распределению совпадает с обучающей.
- Метка определяется правилом на признаках, а не событием отказа в будущем.
- Скользящие средние и приращения считаются по всей серии без разделения на циклы.

## Что планирую дальше
Определять метку по времени до отказа («отказ в ближайшие N часов»), сделать циклы разными по длине и скорости деградации, считать признаки внутри каждого цикла, сравнить Random Forest с простой моделью (логистическая регрессия), проверить подход на открытом датасете (например, AI4I 2020).
